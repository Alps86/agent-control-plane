# Paperclip: Quellenlage und korrigierter Kernabgleich

Stand der Sichtung: 24.09.2026. Diese Planung beschreibt **Zielumfang**, keinen implementierten Stand von Agent Control Plane. `Ist` bedeutet nur, dass die aktuelle offizielle Paperclip-Dokumentation einen konkreten Bedienablauf oder eine aktuelle Implementierungssemantik beschreibt. `Alpha/Experiment` bezeichnet ausdrücklich so markierte Funktionen. `Roadmap` bezeichnet Entwürfe und Zieltexte ohne belegten Ist-Ablauf. Die Dokumentation kann der veröffentlichten Version voraus sein; vor Implementierung wird die konkrete Paperclip-Referenzversion festgeschrieben.

## Verbindliche Grenzen für Agent Control Plane

Paperclip ist funktionale Basis und kein Vorwand für eine kleine Demo. Der POC ist die erste Lieferwelle; bestätigte Funktionen bleiben im Katalog. Eigene Umsetzung: Go-Server, Eino und nur bei beweisbarer Fachfähigkeitsgrenze ein Codex-CLI-Profil, SQLite, UI für Nichtentwickler. Es gibt keine Anmeldung/Registrierung an der Anwendung und keine Budgetverwaltung, Budgetfelder oder Budgetlimits. Anbieteranmeldung für Modellzugang ist etwas anderes. Menschliche Paperclip-Boardrollen werden für den lokalen Betreiber als Bedienverantwortung und für Agenten als fachliche Zuständigkeit übersetzt; daraus entstehen keine App-Accounts. Kosten-/Budgetteile von Paperclip-Exporten, API und Freigaben sind ausgenommen. [Produkt](../../produkt.md), [Technik](../../technik.md), [Modellzugang](../../modellzugang.md).

Das Quellenregister belegt und klassifiziert Paperclip-Funktionen unabhängig von der Story-Reihenfolge. Der [Kern-Storykatalog](storykatalog.md) nutzt die Quellenkürzel als Belege; seine Story-IDs in diesem Abgleich sind Zuordnungen und keine Voraussetzungen für das Quellenregister.

## Offen sichtbare Paritätskanten

1. **Adapter-/Connector-Katalog:** Paperclip dokumentiert viele Laufzeitadapter und etwa 50 Connectoren. Für ACP ist Eino verbindlich; Codex CLI ist nur als Profil verfügbar, wenn seine Tool- und Nebenwege die Fachfähigkeitsgrenze beweisbar einhalten. Die Gleichwertigkeit jedes weiteren Anbieters braucht eine einzelne Schnittstellen-, Rechte- und Testentscheidung; offene Sammelstory INT-05. Kernanbindung für OpenRouter/Voice/Teamchats wird mit der anderen Planung abgestimmt.
2. **Experiment/Alpha:** Plugins, isolierte Workspaces, Chat-Style Tasks, Environments, External Objects, Cloud Sync und weitere Experimental-Flags werden in EXP-01 inventarisiert. Cloud Sync ist nach [Export/Import](https://docs.paperclip.ing/guides/power/export-import/) als Ablöseweg bereits überholt; kein stilles Versprechen eines Cloud-Dienstes. [Experimental Overview](https://docs.paperclip.ing/experimental/overview/).
3. **Menschen/Mitglieder:** Board-Accounts, Einladungen und Login-Rollen von Paperclip widersprechen „keine App-Anmeldung“. Menschliche Arbeit und Entscheidungen bleiben als lokale Betreiberaktionen möglich; Mehrnutzer-/Rechtezuordnung ohne Identitäten ist offen. [Members & Access](https://docs.paperclip.ing/guides/org/members-and-access/).
4. **Workspaces und Sicherheitsniveau:** Produktagenten erhalten niemals direkten Shell-, HTTP- oder Dateisystemzugriff. Codex CLI bleibt gesperrt, falls dies nicht beweisbar ist. Nur die Go-Anwendung darf über validierte Fachfähigkeiten begrenzte Artefakte schreiben; daraus folgt kein pauschales Sandboxversprechen. [P15](https://docs.paperclip.ing/guides/projects-workflow/workspaces/).
5. **Direkter Abo-Modellzugang für Eino:** Verbindliche Nutzeranforderung, aber Integrationsnachweis MS-01 offen; [modellzugang.md](../../modellzugang.md) ordnet die alten MOD-01 bis MOD-05 ausschließlich als Legacy-Aliasse den kanonischen MS-Stories zu. Ein Codex-CLI-Lauf belegt diesen Pfad nicht.
6. **Weitere aktuelle Oberflächen:** Command Palette, Adapter Manager, Skill Policy und strukturierte Task-Rückfragen waren in der alten Matrix nicht erfasst. Sie stehen als NAV-01, AGT-06, SKL-03 und TASK-07 im Katalog. [P20](https://docs.paperclip.ing/guides/day-to-day/command-palette/), [P21](https://docs.paperclip.ing/reference/api/checkbox-confirmations/).
7. **Cases:** Die API nennt sie ausdrücklich experimentell. Im EXP-Inventar bleiben sie sichtbar; sie sind keine still vorausgesetzte Kernaufgabe. [P22](https://docs.paperclip.ing/reference/api/cases/).
